# Zircon 掌机 Menu：统一全屏手札设计

> 本文及网页是设计参考。Godot 掌机客户端现已接入全屏手札；实际入口、操作与验证范围见[运行包说明](../README.md#掌机操作trimui-smart-pro--tg5040)。
> 原型里的角色、属性、物品、任务和操作结果均为示例，不代表当前数据库内容。

- 目标设备：TrimUI Smart Pro / TG5040，物理屏幕 1280×720。
- 设计坐标：640×360；原型用 1280×720 绘制同样的比例，设备可用 2×输出。
- 原型：[zircon-handheld-menu.html](zircon-handheld-menu.html)（单文件，样式和脚本内嵌，参考截图仅保留来源链接）。
- 入口：右侧 **Menu**；**Start 继续切换默认 / 掌机 HUD**，不再占用为主菜单。
- 适用范围：掌机专属 UI。桌面的默认/legacy 窗口、键盘、资源布局不作替换。

## 1. 参考与取舍

实际查看了以下 Switch 游戏截图，而非只参考文字攻略：

1. [《王国之泪》Inventory](https://interfaceingame.com/screenshots/the-legend-of-zelda-tears-of-the-kingdom-inventory/)：左侧分类与物品网格，右侧人物预览和当前物品说明，底部固定操作提示。
2. [《旷野之息》Armor](https://interfaceingame.com/screenshots/the-legend-of-zelda-breath-of-the-wild-armor/)：分类/焦点/已装备状态各自独立，装备前比较数值。
3. [《旷野之息》Weapons](https://interfaceingame.com/screenshots/the-legend-of-zelda-breath-of-the-wild-weapons/)：用物品图标而非密集文本表格作为第一层浏览信息。
4. [《王国之泪》Character Profiles](https://interfaceingame.com/screenshots/the-legend-of-zelda-tears-of-the-kingdom-character/)：固定顶部页面导航，下方列表与详情分栏。这是人物名鉴，不是林克装备页；仅参考信息结构。
5. [《王国之泪》Mini Guide](https://archive.org/details/the-legend-of-zelda-tears-of-the-kingdom-mini-guide-english)：核对 L/R 页面切换、排序和库存管理语义。

**借用：**固定分类层级、大图标网格、明确焦点、人物与比较信息、统一底部按钮图例。

**不照搬：**林克/海拉鲁/希卡视觉素材、3D 模型、实时高斯模糊、单机暂停与即时读档、过长的全物品横向选择条。

Zircon 还有独有约束：旧版物品占多格、左右戒指与手镯槽、10 格快捷腰带、主动/开关/被动技能、服务端权威。新界面应重新组织这些规则，而非改变它们。

## 2. 基本结构

```text
┌ 角色/等级 · 生命状态              世界继续运行 · 负重 · 金币 ┐
│ L1  背包  人物  技能  任务  社交  系统                R1 │
│ L2  当前主 Tab 的分类                              R2  │
├─────────────────────────┬─────────────────────────────┤
│ 物品网格 / 技能网格 / 列表│ 人物预览 / 比较 / 详细说明     │
│                         │                             │
│ 当前页数、容量、空状态    │ 当前动作与限制                │
├─────────────────────────┴─────────────────────────────┤
│ A 主操作   B 返回   X 次要操作   Y 排序/页内动作    Menu关闭│
└───────────────────────────────────────────────────────┘
```

六个主 Tab 的顺序始终固定。禁止“Tab 太多就横向无限滚动”：低频功能并入子页，情境服务另用专用页面。

### 屏幕分配

640×360 逻辑设计：

| 区域 | 建议高度/位置 |
|---|---|
| 顶部状态 | 34 px；不以大量生命心形替代传奇实际 HP 数值 |
| 主 Tab | 36 px；六项都带图标与文字，选中下划线和焦点明确 |
| 子分类 | 30 px；L2/R2 提示、当前筛选、必要时显示排序方式 |
| 主内容 | 约 224 px；左 295 px、右约 298 px，内边距 16 px |
| 操作图例 | 36 px；根据当前页变化，A/B 的含义保持稳定 |

实装中文主体字体建议不低于 11–12 逻辑像素；物品名、标题可用 14–16。底部只显示当下适用动作，不把帮助文档塞进一行。低优先级说明用详情展开或滚动。原型里的小号注释用于说明设计，并非最终设备字号验收。

### 视觉方向

- 墨绿/炭黑底、米白文字、暗金焦点、灰绿辅助文字；保持传奇的材质感，避免照抄塞尔达纹样。
- 物品本身使用当前图库原生像素画；不把图标随意拉长，不在运行时做 AI 放大。
- 人物使用已有 **2D 纸娃娃**。旋转提示在正式版替换为已支持的朝向切换；不承诺新增 3D。
- 网格始终稳定。焦点用实线边框/角标，当前已装备使用第二种底色加“已装备”，不能只靠颜色区分。
- 背景优先静态暗色。可以考虑开菜单时截取一次世界画面并暗化；禁止每帧回读/实时模糊拖慢 fbdev。

## 3. 页面信息架构

| 主 Tab | 子分类 | 主要内容与动作 |
|---|---|---|
| 背包 | 全部、装备、消耗、材料、任务、腰带 | 物品、数量、负重、金币；装备、使用、查看、腰带链接、明确确认的丢弃；腰带含自动喝药入口 |
| 人物 | 装备、属性、抗性、称号、坐骑 | 2D 人物、所有可用装备槽、装备替换差值、套装/来源展开、上下马与坐骑状态 |
| 技能 | 已学、主动、开关、被动、未学 | 完整技能书、等级/经验、耗蓝/冷却/条件、收藏、既有快捷栏组绑定 |
| 任务 | 全部、进行中、已完成 | 目标、当前进度、追踪、前往地图；未完成交付仍走 NPC |
| 社交 | 好友、组队、行会、邮件、排行 | 聊天/邀请、成员与权限、通信与附件、服务端已有榜单 |
| 系统 | 显示、音频、操作、游戏、帮助、离开 | 现有配置、掌机操作图、自动喝药设置入口、登出与返回启动器 |

说明：原型只画了人物的八个核心装备槽，以说明布局；**不是删减装备位**。正式版必须覆盖当前可用全部槽位，可用分页或“战斗装备 / 其他 / 钓鱼装备”页内分组。图标/文字不可用时应有明确占位，不伪造属性。

### 不占顶级 Tab 的内容

- 地图：保持 Select 快速入口，进入/关闭后恢复原 Menu 页。
- 腰带：在“背包”页中管理，D-pad 下快速调用。
- 自动喝药：从腰带子页进入配置，不另占主 Tab。
- 人物外观编辑、技能详情、货币说明、物品拆分数量：局部子页或对话层。
- 公告、邀请确认、注销/退出、删除邮件/丢弃等：弹层，不能成为普通标签。
- 仓库、商店、出售、修理、交易、锻造/镶嵌：NPC/服务端触发的情境页面。
- 当前关闭的商城、寄售、副本、宠物：不在新界面重新开放，也不显示可点的空承诺。

## 4. Menu 与快捷选择器的职责

| 入口 | 目的 | 允许动作 |
|---|---|---|
| Menu | 全量管理与查看 | 分页、筛选、配置、物品动作、装备比较 |
| D-pad 上 | 战斗技能快选 | 选定可施放技能、确认使用；可优先显示收藏 |
| D-pad 下 | 战斗腰带快选 | 在完整快捷链接中选择并使用 |
| Start | HUD 版本切换 | 默认 / 掌机 HUD，不与 Menu 混用 |
| Select | 地图 | 单独快速开关，返回到原页面 |

**全屏技能页不直接施法。**玩家在这里按 A 是配置或看详情，不会因为翻页过程中误按 A 放出技能。主动使用由 D-pad 上的快捷选择器承担。

收藏仅改变掌机本地快选顺序，不改变技能学习状态。若修改既有 F1–F12 栏组绑定，则必须明确提示“更改该角色共用快捷栏”，并使用现有持久化/发包链路；不能在背后临时改 F 键来模拟施法。

## 5. 按键设计

### 全屏 Menu 内

| 按键 | 固定职责 |
|---|---|
| Menu 短按 | 打开/关闭手札；记住上次主 Tab、子分类、焦点和滚动位置 |
| L1 / R1 | 上一个 / 下一个主 Tab |
| L2 / R2 | 上一个 / 下一个子分类 |
| 十字键 / 左摇杆 | 在网格或列表内移动焦点；按住按固定时间节拍重复，不依赖帧数 |
| 右摇杆 | 滚动长详情；人物页可用已实现的朝向切换，不再当鼠标 |
| A | 当前项目的主操作：通常打开物品操作菜单，而不是立即丢弃/替换 |
| B | 取消当前动作 → 收起弹层 → 关闭 Menu；每次只退出一层 |
| X | 当前页显示的次要动作：背包腰带链接 / 技能收藏 / 任务地图等 |
| Y | 排序或页内动作，底部明确标识。排序“浏览顺序”与真正整理背包必须区分 |
| L3 / R3 | 非必要辅助，不承载任何只有按下摇杆才可达的关键操作 |
| Start | 切换 HUD，但不提交物品动作；若有数量/确认框先取消/要求确认，不吞掉未提交状态 |

打开 Menu 后 L2/R2 不喝药，L1/R1 不切战斗技能栏，方向键不打开快捷轮盘；这些键完全归当前 UI 状态所有。

### 焦点规则

1. 记忆键：角色 + 主 Tab + 子分类；仅保存物品稳定身份/源槽，不把瞬时排序索引当身份。
2. 网格使用方向向量选择最近合理邻居。多格物品只拥有一个焦点，任何占格都映射同一物品。
3. 在边缘不意外跳 Tab。主 Tab 只由 L1/R1 切换。
4. 操作菜单打开时 L/R 不穿透；B 关闭菜单后回到原物品，而不是跳第一个格。
5. 物品被服务端删除/移动时，取消旧操作并落到最近有效项；不能继续对过期源槽发请求。
6. 关闭 Menu 后，要求正在按住的方向/攻击/使用键先释放，防止角色立刻跑走、攻击或喝药。
7. 锁定、无法使用、冷却、背包已满等必须给出原因，不能仅静默不响应。

## 6. 背包与人物的关键流程

### 装备

选择装备 → A 操作 → 选择具体装备槽（尤其左右戒指/手镯）→ 看当前与候选差值 → 确认请求 → 等服务端回包刷新。

- 保留旧版多格占位/滚动规则。不允许为视觉统一而改真实库存容量。
- “全部”展示原始占格；筛选可淡化其他分类或建立浏览投影，但不移动源数据。
- 真正的“整理背包”独立于 Y 浏览排序，走现有业务入口；若现有服务不支持，先不提供。
- 观察者/死亡/骑乘/锁定等条件继续由原有规则判定。

### 使用与腰带

选择消耗品 → A 操作 → 使用一个，或 X 选择腰带槽 → 建立/替换链接。

- 显示完整 10 格 BeltLinks；旧版桌面腰带只显示 6 格不等于服务端只有 6 格。
- 使用必须解析真实背包物品，并沿用 `UseItem` 检查、冷却、数量与锁定；快捷链接不是可复制的物品。
- 空槽保留编号；耗尽显示数量 0，不偷偷移走其他槽。
- 绑定到有物品的快捷格需要明确“替换链接”提示。

### 技能

已学 / 未学 / 被动 / 开关分开。显示等级、经验、资源消耗、冷却、装备依赖和当前栏组。

- 未学技能只看条件，不可绑定成可用技能。
- 被动只看说明，没有施放动作。
- 配置现有键位时维持当前去重规则与服务端持久化。
- 收藏为掌机快选筛选，实际快捷施法仍经过原 `UseMagic` 校验和目标处理。

## 7. NPC 与情境页面

统一视觉不等于统一打开权限。服务页需要真实上下文：

| 情境 | 布局 | 关键保护 |
|---|---|---|
| 仓库 | 我的背包 / 仓库 双栏 | 服务端容量与存取条件、源槽、数量、物品锁定、上下文消失时取消 |
| 商店 | 商品列表 / 我的物品与详情 | 显示价格、货币、可买/可卖条件；不把购买直接变客户端加物品 |
| 出售 | 背包出售模式 / 本次选择 | 当前 NPC 可售类型、锁定物品、金额与数量确认 |
| 修理/锻造/镶嵌 | 可处理物品 / 服务结果与费用 | 资格、费用与结果全部服务端校验；不可用动作说明原因 |
| 交易 | 我提供 / 对方提供 | 双方确认状态，任一方变更内容撤销旧确认；取消交易与关闭 UI 区分 |
| NPC 任务 | 对话/任务列表 / 目标或奖励 | 原有接受、交付、奖励资格；对话文本可滚动，选项完整可达 |
| 邮件 | 列表 / 正文与附件 | 未领取附件不能随意删除；领取、发送、删除等待回包 |

服务页中的顶栏缩减为当前允许的页/动作，不允许在交易锁定时用 R1 跳到另一个页面绕开状态。离开距离、NPC 消失、服务器关闭时安全取消操作并返回世界/上级页。

## 8. 状态机与输入优先级

```text
World
  ├ Menu → HandheldMenu(tab, category, focus)
  │          ├ A → ActionMenu
  │          │       ├ 装备槽 / 数量 / 腰带链接 / 危险确认
  │          │       └ B → HandheldMenu
  │          └ Menu/B → World（等待按键释放）
  ├ D-pad ↑/↓ → QuickSkill / QuickBelt → A/B → World
  ├ Select → Map → Select/B → PreviousUI
  └ NPC/服务器事件 → ContextService → Confirmation → PreviousUI / World
```

输入优先级：系统电源/音量 → 当前确认框/数量框 → 输入键盘 → 操作菜单 → 情境服务 → 全屏 Menu → 快选面板 → 世界。一个实体按键只执行一种当前状态动作，处理后停止传播。

网络继续处理，绘制继续显示必要生命/连接状态；暂停的是本地操作意图，不是服务器时间。打开菜单时取消自动跑步、追击、拾取路径、旧鼠标拖拽和未提交施法瞄准（已经被服务器接受的动作不可回滚）。

## 9. 性能与实现边界

- 不新增每帧 `glReadPixels`、实时高斯模糊或 3D 人物渲染。
- 单一全屏容器，页面惰性创建/复用；图标用现有资源缓存，避免每次焦点移动重建全部节点。
- 最多绘制当前页可见网格；长列表虚拟化/分页，滚动条与页数可见。
- 中文字体使用已有字体与静态资源，不将文本栅格后重复放大。
- 切换动画最多轻微明暗过渡，提供关闭选项；不以动画完成作为按键可响应条件。
- 新掌机外壳单独维护，不强行重用旧窗口像素坐标；只复用模型、动作入口和协议约束。
- 维持 `AutoLoginArgs.Handheld` 与独立 UI 模式门控；普通桌面不创建新全屏壳层。

## 10. 设计时的代码接入建议

- 容器：独立 `HandheldMenu` / page model，不再把 `OpenConfigDialog()` 当作全部 Menu。
- 输入：在掌机输入状态路由中处理 Menu；菜单开启时独占 Tab/子分类/A/B/X/Y。
- 数据来源：`GameScene.Inventory`、`Equipment`、`BeltLinks`、`UserMagics`、`PlayerStats`、任务与通信状态。
- 保留动作链：`DXItemCell.UseItem`、装备移动、`SendBeltLinkChanged`、`SendMagicKey`、NPC/交易/邮件请求；不要直接改数组伪装完成。
- 背包：参照 `InventoryDialog` / `DXItemGrid` 的 legacy footprint，使用稳定源槽。
- 人物：参照 `CharacterDialog` / `PaperDoll`，分页覆盖所有可用装备槽。
- 技能：参照 `MagicDialog` 的学派、已学/未学、被动、当前栏组与去重逻辑。
- 情境服务：从既有 `OpenNpcStorage`、NPC shop、trade 等入口进入对应掌机页面，而非另开权限路径。

## 11. 实施与验收顺序

### 第 1 批：外壳与导航

Menu 开关、六主 Tab、L/R 与 L2/R2 导航、焦点/页面记忆、嵌套返回、世界输入屏蔽、退出后释放键门控。默认/掌机 HUD 双向切换回归。

### 第 2 批：核心三页

背包 + 人物 + 技能。优先真实资源、占格、属性比较、完整腰带链接、配置而非误施法。保持桌面完全独立。

### 第 3 批：日志与系统

任务、好友/组队/行会/邮件/排行、设置与安全离开。所有空状态、冷却/不可用原因都有文字。

### 第 4 批：情境服务

仓库/商店/出售/修理/交易/NPC任务逐项接入；逐个验证服务端回包、取消、距离失效与断线。

### 必须实机验收

- 640×360 内部渲染 → 1280×720 屏幕下中文与图标可读，不只看桌面网页。
- 每页全程仅靠实体键可操作，无需鼠标、触屏或必需 L3/R3。
- 物品多格、双戒指/手镯、锁定、背包已满、空腰带、耗尽、被动/未学、冷却。
- Menu 内按 L2/R2 不消耗药品；按方向键不走路；A 不执行第二条鼠标动作。
- 连按/长按/30ms 点击与低 FPS 下均正确；Select 与 Start 职责不冲突。
- 被攻击、死亡、断线、NPC消失、交易对方变更时可安全返回。
- 桌面默认键盘、legacy HUD、现有窗口的回归与配置保留。

## 12. 原型验证范围

网页原型已验证：

- JavaScript 语法检查；六个主 Tab 与共 30 个子分类页面均可渲染。
