## 1. 判据（自写实现，不复用生产解析）

### 1.1 `.map` 解析

```
0..21   22 字节头
22..23  u16 LE Width ;  24..25 u16 LE Height
26..27  跳过
28..    地面层 (W/2)*(H/2)*3 字节
之后    全分辨率格区：格长 stride ∈ {13,14}（**按 (len - 地面层)/(W*H) 精确整除自动识别**）
        格索引 = x*Height + y（列优先）；格内位移 0 = flag
通行判据：(flag & 0x03) == 0x03
```

* 硬编码 14 会把发行数据里 **39 张 13 字节/格**的图（`D601–D619`、`0_00xx`、`d60x–d61x`、
  `kt0002–kt0018`…）整体误判为全阻挡；本脚本对每张图先算 stride，
  `(len - 28 - (W/2)(H/2)*3) % (W*H) != 0` 或商不是 13/14 → 直接判「图异常」并把该条标为
  需人工，**不猜**（实测：把 `d903.map` 截断到 400000 字节 → 5 条 d903 项全部
  `manual_map_parse_error`，脚本不再动它们）。

### 1.2 索引约定自检（**不能**用连通性 coherence）

coherence（可站格的四邻域也可站的比例）**对行/列转置不变**，无法判定 `x*H+y` 还是 `y*W+x`；
它只能判步长 13/14。本脚本改用**独立锚点**：

> 取库里的 NPC / 刷怪 / 安全区 / 传送端点区域中 `PointCount==1` 的坐标（由**另一条产出流程**
> 写下、预期落在可站地面），分别按两种约定求「命中可站格」的比例。

实测（每图最多 8 个锚点，取前 48 张有引用的图）：

| 约定 | 命中率 |
|---|---:|
| 列优先 `idx = x*Height + y` | **1.000**（135/135） |
| 行优先 `idx = y*Width + x` | 0.607 |
| 参考：这些图的平均可站格占比（≈ 随机命中率） | 0.373 |

列优先显著占优 → 脚本继续；否则抛 `ConventionError` 以退出码 3 拒绝执行
（实测：`--maps-dir` 指向缺图的目录 → 「锚点样本太少，拒绝执行」）。

### 1.3 与审计逐条对账

脚本用**自己的解析器**把审计 JSON 里 1757 条连接 × 2 端点的 `walkable` 全部重算一遍：
**3514 / 3514 一致**，0 处不一致 → 两边解析逐格等价（这是「不与生产工具共用错误」的交叉验证）。

### 2.1 选点规则（为什么和审计 §4.1 的「最近可站格」列有 4 条不同）

环形搜索（曼哈顿距离 ≤ 8）内所有可站格按
`(位移, -8 邻域可站数, |dx|, |dy|, dx, dy)` 排序取第一：
第一项保证最小位移，第二项在同距离时优先**更开阔**的格（避免落进只有 1 个可站邻居的墙缝）。
审计给的是「同距离的另一个格」，两格都可站、都在同一连通区，差别只是偏好：

| 4747 | (174,117) 距 4 | (176,115) 距 4 | 邻域同 5/8；本脚本同分再取 `|dx|` 最小（保持 x 不变） |

### 2.2 两个「保持原状」的细节

* **#4737 / #4738 共用同一格**（d903 (48,41)）：基线里「去 d904 的门」和「从 d904 回来的落点」
  就写在同一个格上（审计 §4.1 注：该格既是坏门口又是坏落点）。脚本对**同一旧坐标**的多条连接
