# 比奇县（Map 0）地图连接与安全区坐标修复规范与记录 (2026-10-04)

## 1. 概述与背景

在进行经典纯净传奇 3（Mir3 EI）地图移植后，比奇县地图由早期 Zircon 的旧版小地图（350×350）整体更换为官方 EI 原版大地图 `0.map`（800×800）。
地图尺寸与整体地貌布局发生巨变后，数据库 `System.db` 中原有部分连接点（MovementInfo）与安全区（SafeZoneInfo）仍残留着旧版坐标或历史错误连线，导致：
1. **天然洞穴（D001）断连**：比奇大地图上无任何通往天然洞穴的连接传送点，玩家走到天然洞穴洞口无法进入；
2. **跳蚤洞/绝望谷（D401）错连**：比奇东北部洞窟入口 `(764, 206)` 原被错连至深层副本 `d6015`（生死关）；
3. **主干道关口冲突**：比奇通往道馆（1）与蛇谷（2）的西北/东北关口存在遗留的旧版错位点位与雪原错连；
4. **安全区严重漂移**：比奇安全区中心残留旧版坐标 `(160, 233)`，落于西北荒郊野岭，而非比奇城中心大雕像老兵广场；回城卷与死亡复活均掉入野外。

本次任务对上述问题进行了彻底的梳理、修复与多维验证。

## 3. 核心修复细节与陷阱防范

### 3.1 独立对象解耦（MirDB 一对多陷阱）
在原数据库中，`SafeZoneInfo.Region` 与 `SafeZoneInfo.BindRegion` 引用了同一个 `MapRegion` 对象。
如果直接修改 `BindRegion.PointRegion`（例如 25 个出生落点），会导致大范围安全保护区（Region）被同步截断为仅 25 个点。
- **解法**：在修复工具中强制检查，并生成两个独立的 `MapRegion` 对象：
  - `Region`：中心 `(458, 398)`，半径 18 的圆形区域，提供安全区保护（禁止 PK/攻击）；
  - `BindRegion`：中心 `(458, 398)` 邻域 25 点矩形，供回城、出生和随机落点使用。

### 3.2 地图瓦片阻挡剔除（防 Bad Location / Bad Origin）
传奇 3 地图文件（`.map`）采用 14 字节/格的存储布局，格子的 `(flag & 0x02) == 2 && (flag & 0x01) == 1` 为可行走区。
- 若 Region 范围内直接按几何圆生成，不可行走的建筑、雕像、小摊推车等障碍物坐标会被填入 Region；服务端加载时会报大量 `[Safe Zone] Bad Location`；
- 若传送门 SourceRegion 踩在山体瓦片上，服务端会报 `[Movement] Bad Origin`。
- **解法**：开发专用工具 `Tools/MapConnectionFixer`，在生成点集时自动读取并解析 `Debug/ServerCore/Map/*.map` 二进制瓦片阻挡信息，严格只保留可通行点（共筛选出 778 个有效安全保护格），实现服务端 0 报错加载。

### 3.3 清理历史错连与冗余连接
- 彻底删除了比奇误连冰原雪城（82）的幽灵 Movement；
- 彻底删除了旧版东北关口错连道馆的旧冲突连接（Movement #4032 - #4037）；
- 将原错连至 `d6015 (生死关)` 的 Movement #4102 / #4103 修正为正确的 `D401 (跳蚤洞)`。
