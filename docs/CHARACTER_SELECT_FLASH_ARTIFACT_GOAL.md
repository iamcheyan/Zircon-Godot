# 选人界面旧 Zircon 素材瞬闪排查与修复 Goal

## 目标

GodotClient 登录流程的角色选择界面偶尔会在短暂一帧/数帧内闪现旧版 Zircon 新版人物动画/模型素材，随后又显示当前替换后的自制动画。请找出真实根因并修复，不要用猜测、延迟/遮罩掩盖或只调整截图时机来伪装修复。

## 开始前

1. 阅读仓库根目录 `AGENTS.md`，并按其文档路由阅读与登录场景/角色选择/渲染资源最相关的一篇文档，再打开实际源文件。
2. 确认 `git status --short --branch`，保护所有既有未提交文件；不得 reset/clean/覆盖他人改动。当前启动前看到的既有未提交文件（不要触碰）：无（启动者于 2026-10-04 核验）。
3. 本仓库可能有并行 Godot HUD goal。避免与其改动同文件/同 hunk 发生冲突；每次提交前查看最新远端、工作区和近期提交。若确需共享文件，先拉取已推送改动并按最新基线修改，不得覆盖或 force-push。
4. 任何代码/证据修改经验证后立即按精确文件路径 commit + push，不要攒到任务最后。每次 push 后读取远端分支 SHA 验证。

## 调查与取证

- 先复现：通过真实登录流程进入角色选择界面，重复冷启动/返回/重新登录等安全可重复的流程，记录发生频率、发生时序和视口；不得更改生产/共享数据。
- 在复现前、复现中、复现后做高帧率/逐帧截图或录屏取证，证据须来自实际游戏窗口、非模拟 UI/离线拼图。保留能看到瞬闪旧素材的原始截图序列/短视频，并有稳定正常帧作对照；记录分辨率、构建版本/commit、启动参数与复现步骤。若环境不能捕捉到现象，必须明确写明未复现，不得声称已捕获；继续检查代码路径并设计可重复采样。
- 对选人界面相关动画、模型/精灵库、场景切换、异步加载、缓存、CanvasLayer/过渡帧、旧资源节点残留、资源路径/导入缓存逐项追踪。检查代码、场景树与运行时信号/日志，解释为何旧资源会短暂可见、触发条件是什么、为何最终又被替换。
- 根因判断须有源代码位置/运行时观察与截图证据互相支持；不要把“全部替换过”当作已证实的假设，确认当前实际使用的素材路径/帧/模型身份。

## 修复要求

- 修复真正触发瞬闪的生命周期/加载/绘制/缓存问题，保持角色选择动画、登录和角色选择功能正确。
- 不得删除用户资产或更改非相关 UI/HUD 代码；不得修改原版 `Client/`，除非修复确实必须且先说明证据。
- 不得通过隐藏整个选人界面、加任意等待、降低帧率、延迟截图或永久禁用动画规避问题。
- 新增诊断代码若仅用于调查，最终应清理或明确说明保留理由。

## 验收

1. `dotnet build GodotClient/ZirconClient.csproj` 成功；针对性测试通过。
2. 真实客户端走完整登录→选人流程，在原复现视口和至少一个不同窗口尺寸重复测试；至少 20 次可重复的角色选择场景进入/重进/加载周期，观察记录旧素材闪现次数为 0。若无法自动重复，记录每次手工循环与截图/录像时间戳。
3. 修复后提供实际游戏窗口的前后证据（前：旧资源瞬闪证据；后：修复后完整选人流程以及动画稳定帧/连续帧），不得用静态源码截图代替。输出精确复现步骤、根因、修复点、验证次数与任何无法验证项。
4. 做必要登录功能回归；不更改数据库或写入测试角色数据。
5. 所有独立修复与证据均按小范围精确 staging 提交并 push。提交前检查 `git diff --cached --check` 与 staged 文件 allowlist；每次提交后读取远端分支 SHA。结束时确认 `git status --short --branch`，报告未解决风险。

## 交付物

- 本任务源代码修复（若根因属源码）。
- 根因与复现报告：`docs/CHARACTER_SELECT_FLASH_ARTIFACT_REPORT.md`。
- 经脱敏、真实客户端采集的证据，存于 `screenshots/character-select-flash/`；如出现旧资源闪帧，用连续帧/短视频保留时间顺序。避免提交无关或过大的二进制文件；若确有较大录屏，提供本机证据路径、大小和哈希，并在报告解释未入库原因。
- 最终摘要包含根因证据、修复、验证数据、截图路径、commit SHA、远端 SHA、未验证项。

## 不可妥协

- 不得因编译成功/agent 自报完成就宣布通过，必须实测真实登录与角色选择流程。
- 用户资产优先；不触碰并行 goal 的未提交修改。
- 遇到不可访问资源、无法复现、测试账号占用或必须做超出本地测试边界的操作时，记录 blocker，不要擅自改生产数据或绕过安全边界。
