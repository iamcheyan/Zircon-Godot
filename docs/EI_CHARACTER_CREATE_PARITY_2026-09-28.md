# EI 原版「新建人物」界面 parity 复核（2026-09-28）

本文档针对 EI（传奇3.0 复古 UI）**新建人物 / 创建角色界面**（原版 stage 2）做逐项对照，
并记录本轮按原版证据完成的修复与实机验证。选角列表（原版 stage 0）见
[`EI_CHARACTER_SELECT_ANIMATION_PARITY_2026-09.md`](EI_CHARACTER_SELECT_ANIMATION_PARITY_2026-09.md)；
本文含对那篇文档的两处更正（见 §10）。

- 分支：`goal/ei-character-select-animation-mini-20260928`
- 复核对象：stage 1（点「创建角色」→ 过场）→ stage 2（创建界面：背景/控件/两只预览人物/
  职业性别选择/名字输入/确认退出）在 Godot Legacy 移植版的实现。
- 证据级别：`primary-bytes`（原版 EXE 字节/反汇编）、`primary-resource`（原版 WIL 解码）、
  `derived`、`candidate`、`pending`、`blocked`。

## 0. 结论

1. **创建界面背景是 `Interface1c.wil` F80，不是 F50。** stage 0（列表）用 `push 0x32` = F50，
   stage 2（创建）用 `push 0x50` = **F80**（0x4577E1 vs 0x457B09，`primary-bytes`；
   两帧 640×480 且像素明显不同，`primary-resource`）。
2. **创建界面 = 同一张 F80 上的「两只预览人物 + 石台 + 名字框 + 5 个图形钮」**，
   **没有** 260×650 的窗口面板：两只预览是 §6 的 variant 4 帧段，
   锚点来自 0x458910 表；石台 = F81 @(247,384) 164×88（内含三个职业图标），
   半透明暗条 = F82 @(201,434) 256×32（混合 50/255）。
3. **职业选择 = 三枚图形钮（常态帧 91/94/97）**，点击后**重建两只预览槽**；
   **性别选择 = 点击左（男）/右（女）两只预览人物**（把槽号写 `[owner+0x1488]`），
   被选中的那只**播放动画**、另一只**定格在该段首帧**。
4. **确认 = 常态帧 85 的 ✔（发 `CM_NEWCHR 0x65`）；退出 = 常态帧 88 的 ✘**
   （标签串 0x47D64C「确认人物创建」/ 0x47D638「退出人物创建」，`primary-resource`+`primary-bytes`）。
5. 移植版此前在 stage 2 用的是 Zircon 自有的 `NewCharacterDialog` 复刻（260×650 窗口 +
   职业/性别选项盒 + 发型/染色 + Program/Equip 合成预览），其中的职业/性别按钮帧
   （120/121/126/131/115/110/116/111）在目标 `Interface1c.wil` 里**全是空帧**
   （`primary-resource`），人物形象/位置/动画也与原版完全不同。见 §8 差异矩阵。
6. 实机验证：创建界面与**独立正向预测**（只用 `wilsdk` 解码 + 原版绘制约定，
   不依赖被测代码）的**全画布 MAE = 0.011–0.195 / 255**，
   背景残差 **0.00**；帧号识别出屏幕上的帧段随 120 ms/帧推进并正确回绕。见 §9。
7. 「原版运行画面 vs Godot」仍需同版 Windows/DX8 环境才能做，本机不可得 → 该项 **blocked**
   （与选角文档 §8 同一结论），替代取证为 §9 的独立预测对照。

## 2. 阶段机与切换（`[owner+0x930]`）

| phase | 入口 | 行为（本轮实读） |
| --- | --- | --- |
| 0 | 0x4575F3 → 0x457790 | 角色列表：背景 **F50** → 2 槽 → 4 按钮 |
| 1 | 0x457615 | 创建过场：tick `[owner+0x780]` 视频；播完 → **phase=2** + 创建界面初始化 |
| 2 | 0x457604 → 0x457AB0 | **创建界面**：背景 **F80** → 2 预览槽 → F82 → F81 → 5 按钮 → 名字框底 |
| 3 | 0x4576FA | 过场 tick；播完 → phase=0（回列表），若 `[+0x1168] != -1` 则 `0x458B20(idx,1)` |
| 4 | 0x45773C | 进游戏过场 tick；播完 → 0x4570A0 |

`[0x930]` 写点：ctor(0x456C03)=0；**F51 创建钮(0x459AC5)=1**；stage1 视频播完(0x45763D)=2；
**服务器 `0x209`(0x45922F)=3**；**F89 退出钮(0x459D48)=3**；服务器 `0x20D`(0x459465)=4。

**stage 1 → stage 2 的初始化（0x4576B6-0x4576F8，primary-bytes）**：
```
0x458440(&+0x10BC, gender=0, class=0, level=0, name=NULL) + 0x458B20(0, 4)
0x458440(&+0x10FC, gender=1, class=0, level=0, name=NULL) + 0x458B20(1, 4)
MoveWindow(名字EDIT, win+0x120, win+0x195, 0x4B, 0xD, 1) + ShowWindow(edit, SW_SHOW)
```
→ 每次进创建界面都重置为「**武士 + 男/女两只**」，两槽都以 **variant 4** 起播。

过场锁定：鼠标派发（0x459879/0x459A29）只在 phase 0 与 2 分支动作，1/3/4 落到空返回；
1/3/4 的 tick 也不画按钮 → **过场期间输入被忽略**（primary-bytes）。

## 4. 按钮表（帧号 / RECT / 语义）

ctor `0x417550`（`ret 0x24`，9 参数，0x456DA7-0x456EC8 逐条立即数实读）：
`arg1`=WIL 对象（9 个都是 `owner+0x14C` = Interface1c）、`arg2`→`+0x18`、`arg3`→`+0x1C`、
`arg4/arg5`=x/y、`arg8`→`+0x20`、`arg9`→`+0x30`。
绘制 `0x417640` 选帧：**状态 0 → `+0x20`（常态）；状态 2 → `+0x1C`（hover）**
（hover 由 vtable+0xC = 0x4177C0 写状态 2）。

| 对象 | 常态帧 `+0x20` | hover 帧 `+0x1C` | 交替帧 `+0x18` | x,y | RECT | 语义（悬停标签 VA） |
| --- | --- | --- | --- | --- | --- | --- |
| +0x9E8 | **52** | 51 | 51 | 440,93 | 96×26 | 创建角色 |
| +0xA9C | **54** | 53 | 53 | 79,243 | 96×26 | 删除角色 |
| +0xB50 | **56** | 55 | 55 | 259,49 | 96×24 | 开始游戏 |
| +0xC04 | **58** | 57 | 57 | 28,438 | 48×26 | 结束 |
| +0xD38 | **91** | 93 | 92 | 266,419 | 40×38 | 武士 职业 选择（0x47D680） |
| +0xDEC | **94** | 96 | 95 | 308,419 | 40×38 | 法师 职业 选择（0x47D670） |
| +0xEA0 | **97** | 98 | 98 | 352,419 | 40×38 | 道士 职业 选择（0x47D660） |
| +0xF54 | **85** | 87 | 86 | 450,444 | 28×28 | **确认人物创建**（0x47D64C） |
| +0x1008 | **88** | 90 | 89 | 491,444 | 28×28 | **退出人物创建**（0x47D638） |

`primary-bytes`（ctor 立即数 + 0x417550 字段写入 + 0x417640/0x417722 选帧）+
`primary-resource`（标签串 GBK 解码 + 帧像素：F93/F96/F99/F87/F90 是加亮变体）。

**动作**：
- F51 → phase=1 + `CreateChr.wav` + 载 `.\Data\CreateChr.dat` 播放；
- 91/94/97 → `0x458440(&+0x10BC, 0, class, 0, NULL)` + `0x458B20(0,4)`，
  再对 `&+0x10FC` 做同样处理 → **两只预览都换职业并重播**（0x459DAE/0x459E19/0x459EA5）；
- F85（确认）→ `GetWindowTextA` → **先清空输入框** → 空则返回 → 长度 >14 弹提示
  → `0x4589B0` 名字校验 → 通过则 `0x451FE0(name, 1, class, gender)` = **`CM_NEWCHR 0x65`**
  （`'%s/%s/%d/%d/%d'` = 账号/名字/flag/职业/性别；0x459F56-0x45A02A）；
- F88（退出）→ 播 UI 音 + phase=3 + `[+0x1160]=0` + `SetFocus(主窗口)` +
  `ShowWindow(edit, SW_HIDE)` + `0x451F90` = **`CM_QUERYCHR 0x64`**（`'%s/%d'`，
  即"刷新角色列表"；0x459D1D-0x459D8A）。phase 3 的 tick 在视频泵返回 0 后立即回 phase 0。

## 5. 职业 / 性别选择

- **职业**（三枚图形钮）：见 §4，点击即重建两槽（class 变 → 帧段变；锚点也可能变）。
- **性别** = 「点左（男）/点右（女）」：0x459939-0x4599A1 循环 2 个槽，
  `PtInRect([slot+0x28])` 命中 → 若已是选中槽则只写选中值，否则 `0x458B20(slot,4)`
  重播该槽 → `[owner+0x1488] = slot` → `0x4584C0` 刷新显示串。
  `[+0x1488]` 初值 = 0（ctor 0x456C4B）→ **默认选中男槽**。
- F85 提交时读的是**选中槽**的 `[+4]=class`、`[+5]=gender`（0x45A000/0x45A009）。

## 6. 预览人物的资源 / 锚点 / 动画

- 资源 = **Interface1c.wil**（`owner+0x14C`）；**不是** player-composition 的世界角色合成
  （那条路径绑定场景实体 vtable 0x4763C0/0x476480/0x476720 与元素表 0x5600FC，
  本屏无实体/无方向/无坐骑层，`primary-bytes`）。
- 帧段 = variant 4（0x458B20(slot, 4)），同一张 30 条记录表
  （见选角文档 §3，索引 `(gender + class*2)*5 + variant`）：

| 性别/职业 | 帧段 | 帧数 | variant 4 首帧尺寸 | 锚点（0x458910） |
| --- | --- | --- | --- | --- |
| 男武 | 440–457 | 18 | 104×260 | (110,110) |
| 男法 | 1040–1054 | 15 | 100×268 | (110,120) |
| 男道 | 1640–1656 | 17 | 80×258 | (110,120) |
| 女武 | 740–755 | 16 | 84×240 | (400,160) |
| 女法 | 1340–1356 | 17 | 144×250 | (420,115) |
| **女道** | **1940–1954** | **15** | **108×252** | **(425,118)** |

- 每帧 **120 ms**（记录第 3 字 0x78）；计时严格大于 120 ms 才进帧并清零，
  超过末帧回绕到首帧（0x457B63-0x457BD1）。
- **阴影** = 帧 + 20（0x457BE3 `add eax,0x14`）→ 0x460CB0（混合 blit），
  位置 = 锚点 + 该帧帧头 offset，尺寸取帧头（0x457BF0-0x457C35）。
  两槽的阴影都跟随各自推进的帧号（**未选中槽的阴影也在动**，原版如此）。
- **身体**：选中槽 = 当前帧 → 0x45FD50（0x457C42 分支）；
  未选中槽 = **记录首帧** → 0x4645E0（0x457C98 分支，静止）。
- **命中框** = 锚点 + **当前帧**帧头 offset，尺寸取帧头 w/h（0x458A70）。
- **叠加层**（帧 + 40 → 0x457310，3D 贴图页）：g5（女道）的 +40 段（1980-1994）
  在 WIL 里是 256×128 / 256×256 的幂次页，**无 2D 等价物 → 未移植**（candidate）。
- 女性道士样本（用户指定）：帧 1940-1954、锚点 (425,118)、1.80 s 循环；
  帧 1940 的屏幕矩形 = (425-17, 118+76) = **(408,194)-(516,446)**，与实机一致（§9）。
