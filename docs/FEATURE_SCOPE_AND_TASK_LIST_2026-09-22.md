# 当前功能范围与清理任务清单

日期：2026-09-22

## 目标

当前版本以原版传奇的三职业基础行为为基线：战士、法师、道士。不是把所有后续玩法全部删除，而是在三职业和基础循环稳定的前提下，保留能够丰富体验的扩展系统。

## 功能范围决策

### 必须保留

- 战士、法师、道士，以及三职业对应的技能、装备和基础战斗。
- 登录、角色、地图、移动、怪物、掉落、背包、装备、仓库、NPC、任务、聊天、组队、公会、交易和邮件等基础系统。
- 自动巡路、自动战斗。
- 套装、宝石、强化/镶嵌等装备成长玩法。
- 钓鱼。
- 声望、称号、里程碑。
- 后续可用于丰富玩法的活动、副本机制；副本当前不作为基础功能强制开放，先保留代码和数据，待单独评估。

### 当前阶段禁用

- 刺客职业：隐藏创建入口，并由服务端拒绝新建刺客角色。
- 隐士系统。
- 修炼系统。
- 宠物/伙伴系统，包括跟随宠物、宠物猪、宠物窗口、宠物 NPC 入口和宠物快捷键。
- 游戏商城、充值入口。
- 寄售/拍卖入口。
- 副本地下城 Finder 入口；代码和数据暂不删除。

### 不直接删除的内容

协议、数据库模型、资源、技能枚举、服务端处理类和 UI 文件先不物理删除。第一阶段通过配置开关、服务端校验、快捷键拦截和 UI 隐藏实现“不可用”。这样可以避免误删共享代码，也方便以后重新开放声望、钓鱼、宝石或其它扩展玩法。

## UI 规则

禁用功能必须同时处理三层：

1. 主界面按钮、菜单按钮和 NPC 对话入口隐藏。
2. 快捷键不能打开禁用窗口。
3. 即使客户端伪造请求，服务端也拒绝对应操作。

保留功能不得因为本次清理被隐藏，包括自动巡路、自动战斗、套装、宝石、钓鱼、声望和称号。

## 任务清单

### 第一阶段：配置和三职业边界

- [x] 关闭修炼、隐士和宠物的服务端功能。
- [x] 将 `AllowAssassin` 设为 false，并在角色创建界面移除刺客选项。
- [x] 检查已有刺客角色的登录、装备和技能兼容策略；不能因为关闭新建而破坏数据库读取。
- [x] 保留自动巡路、自动战斗、套装、宝石、强化、钓鱼、声望和称号。

### 第二阶段：UI 和快捷键清理

- [x] 隐藏宠物按钮、宠物菜单和宠物 NPC 入口。
- [x] 隐藏游戏商城按钮、充值入口和商城快捷键。
- [x] 隐藏寄售/拍卖 NPC 入口和相关窗口入口。
- [x] 隐藏副本地下城 Finder 入口和快捷键。
- [x] 隐藏隐士、修炼相关标签、按钮和快捷键。
- [x] 清理禁用功能的默认快捷键和宠物模式入口，避免出现“可以打开但没有反应”的入口。

### 第三阶段：服务端保护

- [x] 为商城、寄售和副本请求增加服务端拒绝保护。
- [x] 为宠物、隐士和修炼请求保持服务端拒绝保护。
- [x] 对刺客新建请求保持 `ClassDisabled` 返回。
- [x] 确认保存、登录、角色信息包不会重新把禁用功能显示到客户端。

### 第四阶段：验证

- [x] 编译 ServerCore 和 GodotClient。
- [x] 使用 `login_game.sh -R` 完整重启并登录测试账号。
- [x] 角色创建代码只保留三职业选项，服务端仍拒绝刺客创建。
- [x] 确认背包、装备、对话框打开后人物仍然可以移动。
- [x] 确认自动巡路、自动战斗、套装、宝石、钓鱼、声望和称号入口仍可用。
- [x] 确认禁用功能无法通过菜单、快捷键、NPC 或伪造请求使用。

## 实施原则

先做“可追踪的禁用”，再做物理删除。每完成一个功能组就记录配置、UI、服务端和验证结果；只有在确认没有其它系统依赖后，才考虑删除孤立代码。
