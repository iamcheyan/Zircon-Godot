# 游戏内 GM 巡检台：方案

日期：2026-11-26。范围为 Zircon 测试服的检查入口，不改变游戏规则、正式存档或服务器权限模型。此文先定方案，执行范围见 `GM_INSPECTION_CONSOLE_GOAL.md`。

## 1. 要解决的问题

现在的验收靠 GM 命令、命令行开关和外部截图：`@move` 能证明图能开，`--portal-audit` 能证明某个门可用，`--npc-func-audit` 能证明几项 NPC 功能，但它们分散在启动参数、程序日志和桌面脚本里。人在 PC 或掌机上玩的时候，无法边玩边查、边记。

所以要做的是**一个游戏内的检查工作台**：找到地点 → 到现场 → 用正常玩法操作 → 看真实结果 → 落一条记录 → 继续下一项。它不是第二套 GM 指令面板，也不替代服务端日志。

**核心判断：**「GM 能传送过去」不等于「这个门通」。同理，「NPC 对话框能打开」不等于「买东西真的扣钱、入库」。巡检台把这两类证据强制分开记录，避免自欺。

## 2. 形态与入口

游戏内窗口，跟随现有 UI 体系，PC 与掌机各自适配：

- **PC：** 游戏内快捷键（默认 `F8`，可在现有按键设置里改）打开。窗口可拖动、可关闭，关掉后回到原有鼠标键盘操作。
- **掌机：** `Menu → 手札 → 系统 → GM 巡检`。不占用 A/B/X/Y/L1/R1 战斗键；只占用已有的手札导航键，退出后交回原动作页。
- **权限：** 仅 `Admin` / `TempAdmin` 可见。非管理员不注册入口、不显示菜单项；服务端对每个查询包再次校验，不依赖客户端隐藏。
- **共用一套模型：** 页面、状态和记录格式只有一份，PC 和掌机只是两套渲染与输入。禁止出现「PC 有这个功能、掌机没有」。

## 3. 页面与功能

### 3.1 当前地图（首页）

显示地图名/文件名、坐标、角色等级、技能数、已穿装备数、测试服 `System.db` 版本。常用动作：**查当前地图、测附近传送点、测附近 NPC、记一条、继续上次巡检**。

### 3.2 地图与连接点

- 按名称/文件名搜索，收藏常测地图；显示本图所有出入口，列出 `源坐标 → 目标地图 → 目标坐标`，以及等级、道具、清怪、副本等条件。
- 两个动作必须分开：**到入口旁**（站到门边，由玩家自己踩）和 **直达目的地**（仅用于布置场景）。
- 逐条状态：未测 / 已到入口 / 真实踩门通过 / 目标落点异常 / 条件未满足 / 已知单向。正向、反向独立记录；原版单向门不记故障。
- 目标落点若在地形上不可站，直接标「落点异常」并给出坐标，例如 `D9022 → d903 (196,161)` 这类已发现的旧问题。

### 3.3 NPC

- 按地图、名称、功能搜索；显示所在坐标、头像/外观、入口页和服务类型（商店、仓库、修理、传送、任务、脚本）。
- 动作：**到 NPC 附近**，然后交回正常交互。验收分三层：**能看见 / 能对话 / 功能生效**。
- 功能生效要给可核对的值：金币与背包数量、仓库前后格、传送后的地图与扣费、任务进度变化。不做「弹窗出现了就算过」。

### 3.4 刷怪（只读观察）

- 当前图配置条目、目标数量、实际活怪数、上次补刷时间；出生点分布按区块显示即可，不做热力图。
- 区分**出生位置**与游走后的当前位置；不把玩家引怪造成的聚集当刷怪故障。
- 只允许在隔离测试服执行「清一小块区域并观察补刷」，正式服隐藏该动作。

### 3.5 任务与角色

- 任务：前置、当前步骤、目标 NPC/地图、奖励；提示该步骤当前是否可做。
- 角色：等级、技能、已穿装备、背包负重、关键属性；用于确认「我现在这个号能不能做这项验收」。
- 不同条件用独立测试预设（满级满装备、低等级、指定任务进度），**不改正式存档**。满级号能验界面和装备，但不能替代低等级号验入门限制。

### 3.6 巡检记录与续测

- 一条记录：类型（地图/门/NPC/刷怪/任务）、地图与坐标、预期、实际、状态、备注、时间。
- PC 可截图并连同结果写入本地巡检文件；掌机记录文字与状态，不强行做截图。
- 侧栏显示本轮进度：「已通过 / 异常 / 未测 / 受阻」。退出再进能回到上次位置，不丢记录。
- 结束时导出清单（JSON + 可读摘要），供修复和回归使用；导出内容不含账号密码。

## 4. PC 与掌机交互对照

| 目的 | PC | 掌机 |
|---|---|---|
| 打开/关闭 | `F8` / 关闭按钮 | Menu 进手札 → 系统 → GM 巡检；Menu 或 B 返回 |
| 切主页面 | 左侧导航点击，或 `Tab` / `Shift+Tab` | `L1` / `R1` |
| 切分类/筛选 | 点击标签 | `L2` / `R2` |
| 选择条目 | 鼠标点击 | 方向键 / 左摇杆 |
| 打开详情 | 单击展开 | `A` |
| 返回 | `Esc` | `B` |
| 加入巡检 / 标记状态 | 右键菜单或按钮 | `X` 打开动作，`A` 确认 |
| 搜索输入 | 键盘 | 只在需要时调出软键盘；默认提供「当前地图 / 附近 / 收藏 / 最近」免打字入口 |
| 现场操作 | 关窗后键鼠 | 收起面板，交回摇杆与动作页 |

掌机 640×360 下：一屏只放一层列表，详情单独一屏；长文本分页而不是缩小字号；所有状态用文字加颜色双编码；不使用只能悬停才出现的提示。

## 5. 数据与实现边界

- **已有数据：** 客户端已加载 `MapInfo`、`NPCInfo`、`MovementInfo`，可直接做地图搜索、连接点与 NPC 列表。地图地形可读当前 `MapView.Map`。
- **服务端独有：** 刷怪配置与活怪数、角色详细状态、任务进度。需要**新增只读查询包**，请求与响应都校验管理员；不新增写操作。写入类 GM 命令在首版不进入巡检台。
- **复用：** 逐图、踩门、NPC 功能巡检已有验证逻辑（`GameScene.MapAudit`、`PortalAudit`、`NpcFuncAudit`、`MonsterAudit`），巡检台复用其判定与截图能力，不重写玩法。
- **不做：** 不改战斗、掉落、任务规则；不直接改运行中的 `System.db`；不把巡检记录写进世界库；不引入第二套账号体系。
- **启动：** 仍用现有 `login_game.sh test`，不新增启动器。执行前必须确认该入口登录的测试角色确实带等级、技能与装备。

## 6. 分期与验收

**P0 · 能查、能去、能记（PC 与掌机同步）**
1. 管理员入口与权限校验；非管理员看不到。
2. 当前地图页 + 地图搜索 + 收藏。
3. 连接点列表与「到入口旁」，记录真实踩门结果与目标落点异常。
4. NPC 搜索与「到附近」，记录三层验收。
5. 巡检记录、进度统计、退出再进可续。

验收：同一名带装备和技能的测试角色，在 PC 与掌机上各走完同一条含至少 1 个传送点、1 个 NPC 的路线，得到一致的通过/异常结论；掌机全程不需要键盘；PC 原界面与键鼠操作无变化。

**P1 · 刷怪与任务**
只读刷怪观察、任务步骤提示、测试预设；隔离测试服上的补刷观察。

**P2 · 批量与导出**
多目标巡检队列、清单导出、失败项一键定位；仍不包含写库。

## 7. 已知风险

- 旧地图里存在落点在障碍上的传送门（如 `D9022 → d903`）。巡检台要把它们变成**可见的异常记录**，而不是顺手改数据。
- 桌面与离线审计可能读取不同版本的同名地图（如 `d1602`）。巡检记录必须写清使用的服务端与数据库来源。
- GM 权限操作可能损伤测试存档。首版只读；任何清理、刷新、发物品动作都要单独授权，并只在隔离测试服。
- 掌机小屏容易把三栏强行压缩。宁可多一屏，不可缩小字号或藏起状态。
