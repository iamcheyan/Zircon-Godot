# 目标任务：游戏内 GM 巡检台（PC + 掌机）

日期：2026-11-26。方案见 `GM_INSPECTION_CONSOLE_DESIGN.md`；本文件是可执行范围与验收标准，二者冲突时以本文件为准。

## 一句话目标

让测试者用一个带等级、技能和装备的测试角色，**在 PC 和掌机上都能打开同一个游戏内巡检台**，完成「找地点 → 到现场 → 正常玩法操作 → 看真实结果 → 记录 → 继续」，并留下可复核的证据。

## 前置条件（不满足就先解决，不要跳过）

1. 确认现有启动入口 `login_game.sh test` 登录的测试角色**实际具有**等级、技能和已穿装备；只凭角色名 `TestHero` 不算确认。把实际等级、技能数、装备数写进开工记录。
2. 使用隔离测试服与独立端口，不连正式存档；不改动运行中服务器的数据库。
3. 记录当前 `git status`，保留所有已有未提交工作；只提交本任务相关的最小改动，不 reset/clean/stash。
4. PC 端基线：`GodotClient` 现有界面、键鼠操作、默认 HUD 与掌机模式互不影响；改动前后各跑一次未启用掌机的回归。

## P0 交付项

### 1. 入口与权限
- PC：游戏内快捷键打开/关闭；关闭后键鼠操作完全恢复。
- 掌机：`Menu → 手札 → 系统 → GM 巡检`，`L1/R1` 切页、方向键选择、`A` 打开/确认、`B` 返回；不占用战斗按键。
- 非管理员不注册入口、不显示菜单；服务端对查询包独立校验权限，不信任客户端。
- 记录：入口文件与注册位置、权限判断位置、非管理员实测截图/日志。

### 2. 当前地图与地图搜索
- 显示地图名/文件名、坐标、等级、技能数、已穿装备数、测试服数据库版本。
- 支持按名称或文件名搜索、收藏；掌机可用「当前地图/附近/收藏/最近」免键盘进入。

### 3. 连接点与真实踩门验收
- 列出本图出入口：源坐标、目标地图、目标坐标、附加条件。
- 「到入口旁」与「直达目的地」是两个不同动作；验收必须走「到入口旁 → 玩家自己踩门」。
- 记录状态：未测 / 已到入口 / 踩门通过 / 落点异常 / 条件未满足 / 已知单向；正向反向分开。
- 目标落点不可站时直接标异常并给出坐标（已知例子 `D9022 → d903 (196,161)`），只记录，不修改数据。

### 4. NPC 检索与三层验收
- 按地图、名称、功能搜索；显示坐标、入口页与服务类型。
- 「到 NPC 附近」后交回正常交互。
- 验收分「能看见 / 能对话 / 功能生效」；功能生效必须给出可核对数值（金币与数量、仓库前后格、传送后地图与扣费、任务进度）。
- 至少在 PC 与掌机上各完成 1 个商店类与 1 个非商店类（仓库或传送）NPC 的完整验收。

### 5. 巡检记录与续测
- 记录字段：类型、地图与坐标、预期、实际、状态、备注、时间。
- 显示本轮进度统计；关闭再打开可回到上次位置，记录不丢。
- 记录不写入世界数据库；导出不含账号或密码。

## P0 验收（缺一不可）

- 用同一名带等级/技能/装备的测试角色，在 **PC 和掌机各走同一条路线**：至少 1 个传送连接点、1 个商店 NPC、1 个非商店 NPC。
- 两端得到一致的通过/异常结论；掌机全程不需要键盘。
- 每个结论都能在记录里追到地图、坐标、实际结果和证据文件。
- PC 原界面与键鼠操作回归通过；掌机原有手札与动作页未被破坏。
- 不把「能传送过去」或「弹窗打开」记成通过。

## P1（P0 验收后再做）

- 只读刷怪观察：配置数量、实际活怪数、出生与游走区分；隔离服上的小范围补刷观察。
- 任务步骤与前置提示；独立测试预设（满级满装备 / 低等级 / 指定任务进度），不改正式存档。
- 掌机详情分页、长文本滚动与状态双编码检查。

## P2（按需）

- 多目标巡检队列、清单导出 JSON + 可读摘要、失败项一键定位。
- 仍不包含写库、批量改数据或正式服操作。

## 明确不做

- 不改战斗、掉落、任务、地图数据或传送门落点。
- 不新增写操作接口；不把 GM 指令面板化后直接暴露给非管理员。
- 不新增第二套启动器或第二套账号体系；不直接改运行中 `System.db`。
- 不为了「看起来完成」把未测项标成通过。

## 证据与提交

- 证据目录：`.artifacts/gm-console-20261126/`，按阶段分 PC / 掌机子目录。
- 每个交付项记录：改动文件、实测步骤、PC 截图或日志、掌机截图、已知限制。
- 提交要求：小步提交、只含本任务 hunk；每步先本地构建与相关回归，再推送；掌机部署前先备份并确认退出/恢复链，不恢复抢屏式 ADB 启动。
- 结束报告必须写清：已交付、未交付、未测原因、剩余风险，以及两端一致/不一致的具体项。

P0 全部交付项通过验收，且两端证据齐全、结论一致，才算完成。P1、P2 未完成不影响 P0 完成，但必须在报告里列出实际状态。
