# OpenCode Goal：EI HUD 聊天与详细聊天窗审计、验证及必要修复

代码仓库：`/home/tetsuya/development/zircon`。EI 逆向研究仓库：`/home/tetsuya/development/Mir3-Research`，只读；该工作树当前已有其他用户未提交改动，绝不可修改、暂存、提交、清理或覆盖这些改动。

1. 阅读 Zircon `AGENTS.md`、`docs/TASK_ROUTER.md`、`docs/CLIENT_UI.md`、`docs/VERIFICATION.md`，以及 `docs/LEGACY_UI_PROGRESS_2026-09-25.md`、`docs/handoffs/LEGACY_EI_UI_AUDIT_HANDOFF_2026-09-24.md` 中聊天章节。

4. 以实时 `origin/master` 为准；不切换分支、不 reset/clean、不覆盖现有用户/agent 改动。

## 范围 A：HUD 聊天记录、输入、滚动与发送

以 EI 常驻 HUD 的 F50 聊天记录槽与其下方独立输入条为范围，至少核查：

- 常驻消息接收、消息类型/颜色/发送者文本、显示和过滤、可读性、裁剪/换行、行距、消息上限、最新消息锚点。
- HUD 输入条显隐、点击/焦点、输入字符与中文输入、Enter 提交和清空、空消息处理、消息历史 Up/Down/草稿恢复；发送调用到 `SendChat`/网络 `C.Chat` 的链路。
- 所有实际可用的聊天打开快捷键及其修饰键语义；输入获得焦点时字母、空格、R、Ctrl 组合键必须由输入控件消费，不能误触发游戏功能或窗口切换。依据 EI 的真实键盘证据核对提示文案与行为，不凭 tooltip 推断。
- 玩家名字交互：区分“点击聊天发送者以启动私聊并预填目标”与社交软件式 `@mention/autocomplete`。从 EI 源证据确定是否有真正的 @ 玩家选择/补全；当前代码若只是前缀/输入模板，报告中须如实命名，不得虚构功能或新增未经证实的产品行为。核查中英文玩家名解析是否被限制为 ASCII。
- 频道前缀/模板按钮行为仅验证输入插入、光标和焦点；逐项确认其语义和是否会发送到服务器。

## 范围 B：HUD 入口打开的详细聊天记录窗口

将其识别为 EI HUD 聊天记录入口（目前 `MainPanel.MailButton` 显示“聊天记录(Ctrl+R, R)”）通往 id 8 / GameInter F350 的详细聊天窗 `LegacyChatDialog`。不要把它误当好友/邮件 `CommunicationDialog`，也不要把现代 `ChatOptionsDialog` 混入，除非 EI 证据证明属于本范围。核查：

- HUD 按钮及 EI 快捷键的打开/关闭、重复切换、窗口置顶/焦点，以及窗口关闭后键盘焦点归还；输入焦点时不得被 R 热键关闭。
- F350 根框、历史裁切区、19 行/14px 几何、输入栏、关闭按钮、底部模板按钮及滚动控件的资源身份、实际命中、可见性、裁切、悬停/按下状态。
- 鼠标滚轮、上下按钮、若 EI 证据定义了可交互滚动条再验证拖动；严禁把 evidence-only 的视觉轨道臆造成拖拽控件。顶部/底部边界、消息溢出、向上翻阅时新消息到达的锚点规则、长行行为。
- F350 与常驻 HUD 的消息内容/过滤同步、输入/发送行为、开关前后历史保持；独立记录两个控件是否共用消息模型、输入框或焦点。

## 证据与安全测试边界

- 追踪每项行为的 EI 原始证据 → 当前 Godot 输入/控件实现 → 消息/命令/packet 路径 → 可观察运行结果；区分 `primary-static`、当前 Zircon runtime、旧 `Client/` 辅助参考、推断和待证实。版本/资源身份不明时不得声称 EI 原版像素/行为完全一致。
- 先检查端口、隔离条件和现有测试账号。任何可能改服务端状态的验收必须使用可证明的独立隔离服务端和独立数据库副本；不能证明隔离则只做静态分析/本地控件测试并标为 `blocked`。
- 仓库 `AGENTS.md` 说明常用测试账号有管理员权限。绝不向共享/生产服务端发 `@` 管理命令；不提交任何 `@...`、`!`、`!!`、`!~` 广播/拒绝命令，不发交易、组队/行会、封禁、传送或其它有副作用请求。频道按钮只测本地文本插入；发送验收只用不会被解析为命令的唯一普通文本，且仅在隔离服务器。私聊消息只在有明确隔离的第二测试角色/双方测试客户端时测发包与回包；否则只验证点击姓名预填，标明未验证服务端交付。
- 不把账号、密码、token、Cookie 或私人聊天内容写入日志、提交、截图或报告；控制台仅记录消息长度和类型，不输出正文。截图限脱敏游戏 UI；不归档共享账号/私人消息。禁用命令行把密码明文放入可持久的脚本/进程日志；如启动工具必须传凭据，使用已有私密方法并确保日志不含值。
- 构建：`dotnet build GodotClient/ZirconClient.csproj --no-incremental`。运行测试优先复用 `docs/handoffs/LEGACY_EI_UI_AUDIT_HANDOFF_2026-09-24.md` 与现有隔离流程；先检查包装器是否会结束现存客户端，确认目标后才运行。

## 执行与验收

1. 先做只读逐项矩阵，确认 A/B 边界、代码入口和既有成果，避免重复重写。
2. 复现实际可测的未闭合项；只修复直接证据支持且属于上述范围的最小改动。无需为了达到“完成”而扩大到社交系统、协议 redesign 或其他 HUD 窗口。
3. 真实交互矩阵至少包含：普通文本聚焦/输入/Enter 提交/清空/回显；输入历史上下键与草稿；打开输入快捷键、输入中热键不误触发；A/B 两视图同步；详细窗按钮和 R 的开关/焦点；历史溢出、鼠标滚轮、按钮滚动、顶部底部边界及新消息锚点；点击消息发送者预填私聊（受安全条件限制时降级并记录）；六模板按钮仅插入且不提交；关闭/重开后历史保留。逐项记实际结果及证据文件路径。无法安全做的项目标 `not tested` 或 `blocked`。
4. 用当前可用 EI 资源明确记录资源根、文件身份和视口尺寸。至少截图实际游戏 viewport 的常用窗口；同时检查 `800×600` 游戏视口以及 `1024×768` 窗口/视口适配（若当前启动路径支持）。截图需体现两个范围及关键状态，截图不是行为证据的替代品。
5. 检查非 legacy 聊天路径没有回归；完成构建、相关测试、`git diff --check`、控制台错误检查和最终工作区审阅。
6. 在 `docs/` 写中文结果报告：A/B 功能图、准确术语、EI 原始证据路径/结论、代码入口、交互验收矩阵、截图/日志索引、资源/服务器隔离边界、变更和 SHA、`verified / not tested / blocked / unresolved` 清单。不得宣称“聊天功能 1:1 完成”，除非声明范围逐项闭合且证据充分。

## 提交与推送纪律

- 每个独立改动（源码修复、证据/报告更新）分别针对性验证后，立即只 stage 对应文件、单独 commit 并 push 到当前批准的 Zircon `origin/master`；不得攒提交，不得 force push。
- 每次 push 后读取远端 `refs/heads/master`，核实 SHA 后才开始下一项。若远端有新提交，先 fetch/检查冲突和触及文件；远端意外修改与本任务冲突时先停并报告。
- 不提交 Mir3-Research 文件、不提交凭据/运行数据库/私密日志/未审截图，也不顺手提交已有用户修改。

## 完成标准

任务报告在仓库中并已推送；每项结论如实标注证据等级；真实运行测试或清楚说明阻塞；相关构建和 diff 检查完成；最终远端 SHA 已核实。若外部资源、隔离测试条件或测试对象不足，持续完成可独立静态审计与安全验证，并把未闭合项清楚列出，不编造通过结果。
