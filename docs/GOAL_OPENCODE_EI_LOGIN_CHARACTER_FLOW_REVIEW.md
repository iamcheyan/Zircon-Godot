## 阶段 A：只读基线与逐阶段审计

先检查当前分支、干净度、最近提交、运行服务/客户端和其他 agent。不要切换分支、重置、清理或覆盖现有工作；工作区若出现其他 agent/用户的新修改，先保全并避开，不要将其带入自己的提交。

对以下阶段建立可追溯矩阵，记录原版触发/状态、协议输入输出、EI 资源/视频/音效、坐标与输入可用性、Godot 对应代码路径与现状、证据级别、差异分类和可复现测试：

1. 客户端启动、启动视频/Logo、资源与配置加载、进入登录。
2. 登录表单、输入规则、登录请求、失败/断线/超时提示与重试。
3. 登录成功、角色列表请求和响应、空列表/单角色/多角色、默认焦点和选中状态。
4. 角色切换/选择：人物显示、动画、槽位/职业/性别信息与输入反馈。
5. 创建入口、创建过场、创建页面初始化与控件、职业/性别/名称输入和验证。
6. 创建提交、服务器成功/失败响应、创建过场结束、回到列表及新角色可见/选中。
7. 开始游戏请求、确认/等待、服务器拒绝/断线、成功响应后的过场完整播放与场景生命周期。
