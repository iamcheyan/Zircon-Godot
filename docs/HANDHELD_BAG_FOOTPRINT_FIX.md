# 掌机手札背包占格修复

日期：2026-11-24。只修显示占格和背包网格布局，不修改物品规则、数据库或存档。

## PC 对照与原因

PC/EI 背包大图取自 Inventory 图库，单格以 36×36 像素换算，宽高分别向上取整。不同装备实际占格不同，不能把衣服统一设为 1×1 或把武器统一设为三格。

发现的三个问题：

1. 手札先用服务端物品槽号寻找隐藏背包网格的显示锚点，找不到就保留默认 1×1。物品尺寸不应该依赖是否已经排进隐藏网格。
2. 背包所需行数模拟虽然找到 first-fit 的 x，却始终在第 0 列标记占用，和真实排布不一致，可能严重少算行数。
3. 手札分页把高物品直接压到当前页的行数，并把连续 PC 网格坐标复制到分页画面。长武器会缩格，跨页装备可能截断。

## 修复

- 手札直接调用 PC 网格使用的尺寸解析器，取物品实际 Inventory 图像尺寸。物品图帧与显示图帧使用同一个 `DXItemCell.GetItemDrawIndex`。
- 行数模拟按真实 first-fit 列标记占用。
- 手札至少使用六行背包格；发现更高物品时扩大页行数，不压缩物品占格数。保留每件物品宽高，整件分页摆放，不跨页切断。分类和名称排序可重排位置，不改变占格。
- 图标按整个多格区域等比缩放，不再限制到区域最短边，避免长武器在多格框中仍只画成单格大小。

## 验证

`GodotClient/Tests/HandheldBagFootprintChecks.cs`：

- 复现无锚点时 2×4 武器和 3×3 衣服退化成 1×1；修复后保持正确宽高。
- 验证 first-fit 行数以及网格中每条物品都有锚点。
- 独立读取原 PC Inventory.wil / Inventory.wix 帧头，对比实际物品定义，共 74 件具有该 WIL 有效图帧的物品通过：43 件武器、14 件衣服、17 件消耗品。
- 对照中衣服有 2×3（6 格）与 2×4（8 格）；武器从 1×2 到 2×6 不等；消耗品为 1×1。数字来自当前素材，不能视作所有物品的固定尺寸表。
- 验证 2×6 长武器不压格、整件在页内显示、相邻装备不重叠。
- 全部对比、装备分类对比、退出游戏、绑定编辑、动作集成测试通过。
- 当前工作树构建及只含本次提交内容的隔离构建通过（6 条既有警告，0 错误）。本地 OpenGL 渲染使用真实图像和离线测试物品，非掌机截屏。

可运行：

```sh
dotnet build GodotClient/ZirconClient.csproj
ZIRCON_HANDHELD=1 MIR3_EI_ROOT="$HOME/mir2ei" \
  godot-mono --headless --path GodotClient \
  --script res://Tests/HandheldBagFootprintChecks.cs
```

`ZIRCON_FOOTPRINT_REPORT` 可指定 CSV 比对输出路径；图形显示环境下设置 `ZIRCON_FOOTPRINT_CAPTURE` 可输出 640×360 测试渲染。

本报告的 74 件只覆盖独立 WIL 有效帧对比范围，后期物品的 ZL/StoreItem 回退和实体机最终显示仍需部署后核验。本次未部署或重启掌机。
