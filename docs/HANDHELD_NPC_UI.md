# 掌机 NPC 对话与服务界面

日期：2026-11-25。适用启用掌机模式的 Godot 客户端。本文区分本地自动验证与掌机/服务器验收，不把独立控件渲染当作实机完成。

## 交谈入口

右摇杆选 NPC，按 A 发起交谈。沿用 PC 的 `C.NPCCall` 请求，由服务器检查当前地图、存活及交谈距离。不再强制自动走到 NPC 的阻塞格。

NPC 普通对话使用全屏深灰金色界面：上方 NPC 名称与头像，左侧自动换行的对话正文，右侧带焦点框的回应选项。正文和选项分区，长选项可在左侧「当前回应」查看全文，防止价格被列表省略。右摇杆上下滚动正文，方向键或左摇杆上下选择回应，L1/R1 翻选项页，A 提交，B 结束交谈。进入时要求摇杆回中，防止开窗前输入继续导航。

含冒号的文字选项（如费用）按末尾整数 ID 识别，ID 保持服务器原值。接到新页重置选择；单次选项已发出后，普通对话和服务列表共用同一待回应门控，不用超时重新激活旧按钮。用户可用 B 关闭后重新交谈。无法解析服务器页时清空旧选项并关闭旧服务子面板，不能把旧页当作新页继续提交。

## 服务页与确认

商店、仓库、交易使用同风格双栏服务簿；NPC 的其他服务将已有服务控件投影成操作与物品列表，沿用原按钮、物品条件和网络请求。不绕过价格、职业、容量和服务端校验。仅出售的 NPC 即使没有可买商品也保留出售入口。NPC 服务状态定期重扫，异步生成的结果、领取按钮和开关不会等待背包变化才刷新。

物品数量和费用确认使用掌机专用深灰金色窗口。数量：左右 ±1、上下按原数量步长、A 确认、B 取消，不需要鼠标或文本焦点。费用确认默认「取消」，左右选择、A 执行、B 返回。窗口由 NPC 发起时绑定 NPC 与页修订号；页变化、NPC 失效、断线时不执行旧回调。交易等其他前景服务的提示不绑定到背后仍显示的 NPC。

精炼评估不是消耗提交：评估前不锁材料，不加入等待消耗结果的列表；确认时核对来源物品。普通精炼提交仍沿用结果包解锁流程。数量提示也核对物品/目标格身份，防止回调引用已替换的格子。

## 本地验证

- 当前客户端 `dotnet build` 通过：0 错误，6 条既有警告。
- `HandheldNpcInteractionChecks`：真实 GameScene 响应分发 → NPCDialog → 掌机视图 → 按键 → 待发包队列。覆盖 5 格 NPC 请求、不走阻塞目标格、文字选项含冒号、重复确认只发一包、两个界面共用门控、空页清旧选项、旧确认失效、仅出售服务入口、B 关闭（9 项）。不连接服务器，不扣款。
- `HandheldNpcDialogueChecks`：选项焦点、分页、重复请求、长正文实际滚动、页替换重绘；OpenGL/Xvfb 输出 640×360 截图。正文为离线示例，非服务器真实脚本。
- `HandheldPromptChecks`：数量上下限、零值不可确认、取消默认项、失效回调不执行、重复确认不重复调用及 640×360 缩放边界。
- 退出游戏、绑定编辑、动作集成检查复跑通过。
- NPC 集成夹具退出有 CanvasItem/ObjectDB 未释放警告；不能作为真实会话资源稳定性通过的依据。
