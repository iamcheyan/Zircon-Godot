# Zircon 旧版 EI 对话框迁移实施与验收规范

> 状态：执行中。任何模型接手都必须先读本文和对应证据文件；禁止从当前 Godot 窗口反推旧版尺寸。

## 1. 目标与事实来源

在保留 Zircon 网络、物品、技能和窗口业务逻辑的前提下，对齐 EI 3.0 的窗口尺寸、背景帧、按钮状态帧、格子数量、内部坐标、文字区域、快捷键、打开/关闭及置顶行为。这不是给新版窗口换背景；旧版和新版控件树不同，必须逐窗重建布局再绑定现有业务。

事实优先级：

1. `Mir3-Research/docs/research/ei-ui-layout/` 反编译证据。
2. 原版 WIL/WIX 与 `Magic.exp`。
3. `Mir3-Research/Tools/mir3_client_simulator/data/*.json`。
4. 网页模拟器实现，仅用于复现证据。
5. 当前 Godot 代码只提供业务逻辑，不是布局依据。

冲突时二进制静态证据优先；`candidate` 记录必须继续标记为候选。测试资源从 `/home/tetsuya/mir3ei/LegacyEI/Data` 读取，不覆盖正式资源。

## 2. 已确认的底层问题

`DXImageControl.FixedSize` 只固定控件边界，不改变贴图绘制尺寸。WIL 窗口帧通常包含大块透明画布，不能把整张画布强制缩放，否则有效图像会变小或变形。默认规则是保持原始比例，并根据帧的有效像素边界把透明画布平移到窗口原点。`StretchImage` 只保留给证据明确要求拉伸的控件。交易 F1050 等溢出窗口单独实现。

## 3. 统一实现架构

每个窗口分两层：

- `Legacy layout`：背景、旧版按钮、格子、标签和命中矩形。
- `Binding`：把 Zircon 物品/技能数组、网络操作和回调绑定到旧版控件。

禁止继续移动新版控件来近似旧版。每窗增加旧版布局构建方法，正式游戏和测试场复用同一份控件树。

统一规则：

- 背景默认使用 `FixedSize=true, StretchImage=false`，按 WIL 有效区域原点平移并由窗口裁剪；禁止拉伸有效图像。
- 按钮明确指定图库、普通/悬停/按下帧、坐标和尺寸。
- 格子按证据的起点、行列及步进创建，不使用新版默认值。
- 关闭按钮用旧版 GameInter 帧，不混入 Interface[15]。
- 旧版窗口关闭新版 `DXWindow` chrome、默认标题栏和默认关闭按钮，避免双框、黑边和双标题。
- 同一按钮/快捷键再次触发时关闭；Esc 关闭最上层；点击窗口置顶。
- 测试场允许空数据，但必须复用正式窗口，不能另造假窗口。
