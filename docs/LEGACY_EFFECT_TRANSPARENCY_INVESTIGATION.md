# 特效透明度与施法特效站位：调查记录与未决问题

> 记录时间：2026-10-03 晚 ~ 10-04
> 状态：**部分已解决，核心问题仍未闭合**。本文档记录已用数据验证的事实、已尝试并回滚的改动、以及明确的未决点，避免后续重复踩坑。

## 一、问题描述

用户在 legacy EI 模式下连续三轮反馈：

1. **建角/选角预览**：法师手掌上方的青色光球是**分层**的，底下那层"黑色半透明"一直没实现，看起来很难看。
2. **特效内部**：不该透明的地方变透明/变黑，"中间是黑的"。
3. **新建人物后站位**：人物位置与施法魔法位置**对不上**；魔法特效中间有本该不透明的部分被抠掉。

三张截图分别对应：建角光球边缘、镜像术站位、镜像术黑边。

## 二、已用数据确认的事实

### 2.1 受影响的帧

| 特效 | 库 | 帧区间 | 尺寸 |
|---|---|---|---|
| 法师女青光（选角/建角 +40 层、镜像术） | `Interface1c` | `F1384..F1391` | 512×256 |
| 法师男橙火 | `Interface1c` | `F1080..F1094` | 128×256 |
| 法师镜像术本体 | `MagicEx2`（**仅 ZL 格式**） | `F1260..F1265`（原版 6 帧） | 128×128 / 64×64 |

注意：`MagicEx2` 在 `mir2ei/Data/` 下**只有 `.Zl`**，没有 `.WIL`；而 `Interface1c` 在 `LegacyEI/Data/` 下是 `.wil`。**两条路径走不同的解码器**，这是后面反复踩坑的关键。

### 2.2 黑边的真正来源（已定位）

`Interface1c F1385`（法师女青光，512×256）逐像素实测：

- 原始不透明像素：**52119**
- 其中暗像素（`max(RGB) < 40`）**42215 个**，分布上半 19707 / 下半 22508，
  **均匀铺满整个特效范围**，不是边缘一圈
- 严格近黑（`RGB=(8,8,8) alpha=255`）32717 个，上半 15381 / 下半 17336

这正是用户截图里"下半部分大片黑"的来源 —— 它**本来就在素材里**，不是渲染产生的。
> 注意：早期口头汇报里把"严格近黑 32717"误记成 3388/42215 混用，本表为逐像素复核后的准确值。

### 2.3 连通域抠像对该特效是净损失（决定性数据）

把 `F1385` 的 42215 个近黑像素与帧边缘（上/下/左/右）做连通性分析：

```
暗像素 总=42215  上半=19707  下半=22508
与边缘连通: 42142 / 42215  (99.8%)
不可连通（唯一该保留的）: 73
```

配合实测的像素损失：

| 帧 | 原始不透明 | 经连通域抠像后 | 损失 |
|---|---|---|---|
| `MagicEx2 F1260` | 4139 | 620 | -85% |
| `Interface1c F1385` | 52119 | 813 | -98% |

**结论：连通域扩散会把特效主体整体抠掉，这个方向本身是错的。** 早期"亮度/chroma 一刀切"和"改连通域"两种做法都会摧毁特效。

### 2.4 原版并不做颜色键抠像

`Client/Models/MirEffect.cs:238`：

```csharp
Library.Draw(DrawFrame, DrawX, DrawY, DrawColour, UseOffSet, Opacity, ImageType.Image);
```

`RenderingCore/Library/MirLibrary.cs:279` 的 `ImageType.Image` 分支：直接 `image.CreateImage(...)` 取解码结果，**没有任何颜色键处理**。

即：**原版对"自带 alpha 的 ZL 帧"是直接用的**。4 万个 `(8,8,8,alpha=255)` 像素在原版画面里同样存在。

### 2.5 原版特效的定位方式

`Client/Models/MirEffect.cs:165-172`：

```csharp
DrawX = Target.DrawX + AdditionalOffSet.X;
DrawY = Target.DrawY + AdditionalOffSet.Y;
```

原版对部分特效设 `AdditionalOffSet` 把特效抬高（如 `MapObject.cs` 中 `(0,-50)`、`(0,-64)`、`(0,-25)`、`(10,-25)`）。**`MirrorImage` 原版没有设** `AdditionalOffSet`。

## 三、已尝试并回滚的改动

### 3.1 `c79edccb` —— 已回滚（`53d992c4`）

**做法**：把特效抠像从"按亮度线性折算 alpha（GlowCeiling=200）"改为"按饱和度 chroma 判定键色"。

**为什么错**：原版 `ZlReader.RemoveConnectedEffectBackground` 用的是**四角连通域扩散**（欧氏容差 72），不是逐像素判 chroma。改成逐像素判之后，特效内部同样灰暗的笔画被一起抠空 —— 就是用户报的"中间变黑、不该透明的也变透明"。

### 3.2 `3bfced0f` —— 保留（部分有效）

三处改动：

1. **撤销 `c79edccb`**（恢复原版语义）
2. **`LegacyWilLibrary.GetEffectTexture` 补上连通域抠像**（此前只有简单键色，与 ZL 侧行为不一致）
3. **`MirrorImage` 按原版抄**：`Client/Models/MapObject.cs:4183` 是 `MirEffect(1260, 6, 100ms, MagicEx2, 10, 35)`，此前误写 `1280 / 10 帧 / 光照 0→0` → 改为 `1260 起 6 帧、FrameLight=10`
4. **补 `SpawnCastEffectTarget` 漏接的 `FrameLight`**（原版 MirEffect 一律带 startLight，而 `CastEffect.FrameLight` 在 target 分支从未被读取）

**其中 3、4 有仓库内原版代码为据，可信**。**第 2 项（连通域抠像）经 2.3 验证有害，需要重新评估。**

### 3.3 2026-10-04 本轮 —— 已全部还原

尝试给 `ZlReader.RemoveConnectedEffectBackground` 加"四角 alpha==0 就跳过"守卫。实测该守卫**无效**：四角 alpha=0 只说明角落透明，42215 个暗像素里 42142 个仍与边缘连通。改动已 `git checkout` 还原，工作区回到 `3bfced0f`。

## 五、未决问题（需要原版证据才能推进）

### 5.1 核心：原版如何处理特效里的近黑像素

**已知**：这些像素在原版画面里也存在（用户截图下半的黑即来自此），原版解码器不做颜色键抠像。

**未知**：原版靠什么让这 4 万个 `(8,8,8, alpha=255)` 像素在屏幕上呈现为柔和阴影，而不是死黑块？

已排查但未果：
- `RenderingCore/Rendering/SilkVulkan/SilkVulcanRenderingPipeline.cs:2802` `AppliesBlendRateToVertexColour` —— 只有 `COLORFY`/`MASK`/`EFFECTMASK`/`LIGHTMAP` 四种混合模式把 `blendRate` 乘进顶点色
- 未找到把暗部转成半透明的代码路径
- **原版 `ZlImageCodec` 解码器不在本仓库** —— 这是关键缺口

### 5.2 需要用户确认的判断题

在拿到原版解码器证据前，需要你判断：

- **这个特效的暗部，原版应该是什么样？**
  - (A) 半透明柔和阴影 → 问题在"如何把近黑转半透明"
  - (B) 本来就该是黑 → 问题变成"为什么它盖住了人物"，方向完全不同（绘制顺序/图层/`DrawType`）
- 你的截图里青光**上半干净、下半是黑** —— 这个上下差异是原版本来如此，还是也是 bug？

## 六、方法论教训

本次连续三轮返工（`c79edccb` → revert → `3bfced0f` → 本轮还原），根本原因是**在缺少原版证据时用推测替代取证**：

1. 只看注释和既有代码就断言"素材缺失""不可交互"，没有系统扫描素材库（漏掉了 F630/631/632 三个真实存在的锁链帧）
2. 改代码前没有先量化"改动会让多少像素丢失"
3. 把"离线渲染对比看起来对了"当作验证充分，但未先确认该改动是否作用在**实际生效的代码路径**上（WIL 改动对只有 ZL 的 `MagicEx2` 完全无效，这个事实查了三轮才发现）

**正确做法**：任何特效/渲染改动，先回答三个问题 ——
(a) 这个资源实际走哪条解码路径？（WIL 还是 ZL）
(b) 原版对应代码在哪？（`Client/` 里有源码就必须先读）
(c) 改动的量化影响是什么？（像素保留率）
