# 普通怪地图均匀刷新

`DistributedRespawnMap` 按地图共用一个候选池。普通自然刷新优先选择补入一只后活怪密度较低的 16×16 区块；区块内随机、不放回地挑空格，跨规则不在同一格生成普通怪。候选只来自有效传送/回城落点所在的地形连通片；没有已知落点时选择面积最大的连通片。受保护安全区、传送格、到达格和自然刷新的单点 Boss 专用格永不作为候选。通常避开传送点周围三格；整个小房间都处在缓冲区时，只保留上述排除条件。连通性按地形八方向计算，不模拟玩家的等级、道具或任务门槛。

原刷怪记录仍决定怪种、数量上限、刷新间隔和掉落。地形容量小于普通怪目标时，按目标比例缩减各组上限，而不是先到先得或叠怪。Boss、事件、定时公告、实例、门禁绑定及任务区域规则不进入共享候选池。带游走距离限制的普通怪以实际出生位置为回巢目标。每次成功落地才增加 `AliveCount`；直接移除活怪会释放名额，但不会触发仅用于击杀的清场事件。

## 验证和已知边界

以 `System.db` 2026.10.18.8 和配套地图做离线运行，覆盖有配置的 282 张图 / 2,156 条规则。数据库中没有刷怪配置的 345 张图不新增怪。新策略在 249 张地图应用于 1,931 条规则，其他 33 张有配置的地图只有特殊规则。21 张旧版测试中完全没刷出怪的地图现在都有实际落地对象。比奇（`0`）的普通怪在同一 16×16 分区口径下由 124 个有怪区块增至 145 个，并通过两轮按实际计时补刷。测试数据不是在线玩家实测。

使用 [SpawnDataRepair](../Tools/SpawnDataRepair/README.md) 迁移副本后，`D604` 的普通怪配额为 151；`D605` 为 179，并另留一格给 Arch Lich Taedu。蚁洞八张同系列地图恢复为每图一只蚁将军，配置间隔 120 分钟。`D9031` / `D9032` 恢复缺失的两条原版遭遇。迁移副本的严格审计覆盖 **284 张图 / 2,158 条规则**，全部达到修订后配额，实际生成与存活计数一致。桌面 Godot 通过本地测试服登录和 15 张代表图的进图与渲染检查；这不等于逐图客户端巡检。

- `dotnet run --project Tests/SpawnLifecycleChecks`
- `dotnet run --project Tests/SpawnDistributionChecks -- Debug/ServerCore/Database Debug/ServerCore/Map output.csv`；加 `--legacy` 可在同一数据和正确计数下对照旧落点策略。
- 回退普通怪分布算法：在 `Server.ini` 的 `[System]` 下设置 `DistributeOrdinaryRespawns=False` 后重启目标服务。计数修复仍然有效。地图配额及 Boss、船舱规则修订是独立的数据库迁移，需要另行应用或回退；上线前先备份并核对服务端和客户端 `System.db` 一致。
